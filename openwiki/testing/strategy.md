# 测试策略：槽位、观察层与失败方向

[docs/TESTING.md](../../docs/TESTING.md) 是这套策略的正文，它从两条硬约束推出来：[日常回归零模型额度](e2e-and-mocks.md)与[不产生第二份真相](../architecture/state-ownership.md)。这一页是它的导读，指路到具体判据。

规则都带锚点（日期 / 文件 / 数字），过程细节留在 git log 里。**抽象原则会被「我这次是例外」绕过，带日期的事故不会。**

## 动手前的三个判断

### 一、这条测试进哪个槽

| 槽 | 住哪 | 跑什么 | 命令 |
|---|---|---|---|
| **G** 静态门禁 | `scripts/gates/` | 读源码与配置文本，零 IO | `npm run lint`、`npm run protocol:check` |
| **U** 纯函数单测 | `test/unit/` | import 真模块，不碰磁盘 | `npm test` |
| **I** 带 IO 的单测 | `test/unit/` | `mkdtemp` 真磁盘 / spawn 子进程 | `npm test` |
| **E** 浏览器行为 | `e2e/*.spec.js` | Playwright + mock 后端 | `npm run test:e2e` |
| **M** 变异 | 只在容器 | 改坏源码，看断言开不开口 | `npm run mutate:docker` |
| **S** 真 Codex 冒烟 | `scripts/smoke-*.js` | 真 CLI，烧额度 | 手敲，需授权 |

`test/` 下另有四个目录，它们与 `test/unit/` **执行槽相同**（同一条 `npm test`、同一份预加载），分的是组织轴不是运行轴：

| 目录 | 收什么 |
|---|---|
| `test/unit/` | 按**被测模块**组织。文件名 = 被测模块名 |
| `test/invariants/` | 按**不变量**组织，见[不变量登记表](invariants.md) |
| `test/integration/` | 起真进程 / 连真端口 |
| `test/infra/` | 测**测试基建自身**（`scripts/gates/*`、workflow、`mutate.js`） |

判据按 infra → integration → invariants → unit 的顺序问，第一个「是」就停。门禁自己住 G 槽，测它们的文件住 `test/infra/`——两者不是一回事。

选槽的顺序则是：**能静态看穿吗** → G；**能抽成纯函数吗** → U；**判据是「用户点得到 / 读得懂」吗** → E；其余 → I。

**不新增按「会怎么伤人」分的类别**（`security/` `reliability/` `performance/`）。那是缺陷的后果分类，不是执行槽或组织轴。

### 二、观察点在哪一层

同一个缺陷可以在三层观察，成本差一个数量级，**而它们抓到的东西并不相同**：

- **源码文本**（`readFileSync` + 正则）—— 只证明「代码写了」，不证明「功能能用」。删掉的 `public-ui.test.mjs` 用 1807 行做这件事，删掉后覆盖率一点没掉（91.30 → 91.33），因为它从不 `import`。**不要再往回加这一层**，唯一合法用法是结构性绊线。
- **单元 / 契约**（真 import）—— 默认落点。
- **浏览器行为**（真 `click`、真 `toBeVisible`）—— 判据是可达性与可读性。

选最低的那一层，但要确认它真的看得见你要守的东西。反向例子：MCP 启动状态的静默判定抽成纯函数放在 U，**因为 mock app-server 不发那条通知，这条路径在 E 里根本走不到**，只靠 E2E 的话它会一直是零覆盖。

### 三、失败方向是哪一侧

**本仓的 fail-closed 是逐条选过的，不是「所有异常都该拒绝」。**

| 场景 | 正确方向 | 为什么 |
|---|---|---|
| 读不到 `node --test` 的汇总行 | **失败** | 报告格式变了而我们读不懂时，沉默放行等于把这道门拆了 |
| MCP 报了一个未知的启动状态 | **照报，归告警侧** | 上游随时会加新状态值。漏真故障 vs 多一条消息，代价不对称 |
| MCP 正常的 starting / ready 刷屏 | **静默** | 实测一次对话 8 条系统消息，把回答挤出首屏 |
| devDependencies 有高危漏洞 | **不阻断** | 不上生产。但报告必须留成 artifact |
| 运行时依赖有高危漏洞 | **阻断** | 传输层就是 socket.io，直接暴露在网络边界上 |

写新测试前先回答：这条路径失败时，产品**应该**拒绝还是放行？答案不总是拒绝。

**噪音与告警不共用一个开关**，这是第 2、3 行的一般形式：把告警连同噪音一起关掉，用户就再也不知道某个 MCP 起不来了。

## 落盘隔离是全局的

`test/setup/preload-env.mjs` 经 `node --import` 在任何测试文件之前加载，把 `TMPDIR` 与 `CODEX_DATA_DIR` 一起指进一个 `mkdtemp` 出来的一次性根，进程退出时整棵删掉。

**为什么必须是预加载**：`server.js` 的 `DATA_DIR`、两个审计文件路径、推送订阅路径、`devices.js` 的数据目录全是**模块级常量，import 时就求值**。而 ESM 的静态 import 在模块链接阶段完成，早于该文件自身任何顶层语句——把赋值写在 import 上面也没用。

`TMPDIR` 也一起收，是因为光靠各文件的 `before/after` + `rmSync` 补不上：被测模块的异步/防抖落盘发生在 `after` **之后**，它的 `mkdirSync(recursive)` 会把刚删掉的目录重新建出来。

注入点有两条，都要维护：`npm test` 走 `check-test-summary.js` 的包装器（硬编码，不可能忘）；`test:local` / `coverage` 绕过包装器，在 `package.json` 里各自显式写。

## 变异只在容器里

`scripts/mutate.js` 有硬闸：没有 `CCM_IN_CONTAINER` 直接拒绝运行，**无例外**。

理由不是谨慎：变异会故意改坏源码，而**改坏的可能恰恰是算路径或算删除目标的那段代码**。姊妹项目就是这么删掉过一整棵 `~/.claude/projects`（70 个项目 / 2990 transcript）——`getProjectDir` 被改成恒返回 `''`，`join(真实根, '')` 塌成真实根本身，测试的 `rmSync` 打了上去。

真正挡住它的是容器里那行 `ENV HOME=/home/ccm-test`，**不依赖任何代码正确性**；`mutate.js` 自带的恢复逻辑挡不住——容器被 kill 或变异中断时它根本不会执行。这条是不变量 `TEST-01`。

这是白名单不是黑名单：黑名单要求「每遇到一个新命令都正确归类」，而那正是会失败的一步。

## 假绿：怎么知道自己写的测试在守东西

**看着漂亮却永不变红的测试比没有更坏**——它占着「这里测过了」的位置。

### 两侧验收

一条测试要同时满足：**正常代码下绿**，**注入对应缺陷后红**。只做前者的话，「断言咬住了行为」和「断言什么都没咬住」在输出上完全一样。

三个要点：注入的必须是这条断言声称能抓的那个缺陷；断言顺序决定注入能验到哪一条（实测有一次注入红在前面那条断言上，目标断言根本没跑到）；**修一个假红最容易掉进去的坑是把它改成假绿**——反向断言必须单独验一次鉴别力。

### 变异抓不到的三类

变异改的是**我们自己的源码**，所以下面三类它全免疫：

1. **fixture 编错外部契约** —— mock 与被测代码一起偏离真实协议，两边自洽。[protocol-check 的字段层](../integrations/codex-app-server-protocol.md)就是为这个存在的。
2. **扫描面塌了** —— 凡是「遍历一遍然后说没问题」的脚本，扫到 0 个和全部合规在输出上无法区分。实测：把协议类型声明从 `type` 换成 `interface`，71 个类型的字段一个都读不出，而门禁照样打印 OK 并返回 0。**这类脚本都该有一行「扫到的数量 > 0」断言。**
3. **门禁根本没被执行** —— 见[门禁链路与 CI 接线](gates-and-ci.md)。

### 反复出现的假绿形态

`docs/TESTING.md` 第 3 节列了十余种，都带具体事故。几个高频的：

- 给既有代码补的测试**默认空过**（照着现有实现写的，实现错了它跟着错），补完必须注入验红；
- fixture 停在已经迁移走的格式——改数据格式时要**连带审一遍所有硬编码该格式的 fixture**；
- 测试里出现一份和生产代码平行的清单，那是在复述数据而不是验证行为，正确形态是**从唯一来源派生**；
- 用 `dispatchEvent` 代替 `click` 会绕过 Playwright 的可见性检查，于是整块界面对用户不可达而 E2E 一直绿；
- 「HTML 里有这个 id」不等于「用户点得到」；
- CSS 里「写了」和「生效了」之间隔着特异性与源码顺序，**CSS 不会为此报任何错**，要靠绊线守；
- 整轮 E2E 共享一个 mock server 进程，**审批类用例必须就地 deny 掉**，否则会污染后面的 spec（表现为「单独跑绿、全量跑红」）。

## 增 / 改 / 删功能时做什么

**加功能**：列一张表，行是「这个功能会怎么伤人」，列是槽，不适用的格子写「—」和原因。完成判据三条——该红的格子有**外部可观察**的断言、更便宜的槽能抓住的没有升到 E/S、路径/删除/鉴权相关的至少跑过一次变异。

**改行为**：**先改断言，再改实现。** 反过来做是让测试追认实现，而不是让测试约束实现。

**搬家**：入口换了位置时可达性覆盖必须跟着搬，并断言**总数**——只断言各自「有按钮」的话，搬家途中漏掉一个不会有任何东西变红。

**删测试**：比删生产代码更需要证据——**生产代码删错了会有测试红，测试删错了什么都不会红**。四步流程：逐条为旧断言构造缺陷看新测试会不会红、把真独占的能力搬进新文件、核对 test 总数的减少量**正好等于**被删文件的 test 数、在新文件头写清哪些没搬及为什么。

**交付前**：把验证过程写进 commit。写「已做双向验收」零成本；写「注入 X 到 `file:line` → 精确红 1 条，消息是 Y」写不出来就是没做。有未验证项时 `Not-tested:` 必须写。

## UI 层的两个维度

「不会崩」和「读得了」的交集比直觉小得多：实测宽表格四条结构性断言全绿，而中文列被压到 49px。三个审计库补的就是第二个维度，见 [E2E 与 mock 后端](e2e-and-mocks.md)。

写 UI 规则的三条元规则：**门禁死于误报比死于漏报更常见**（一条在正常代码上报出一片的规则会被整条忽略然后删掉）；**扫描面塌陷的判据不能是「scanned > 0」**（纯图标区域本来就没有文本叶子），真正的失明是「有文本却一个都没扫到」；**为误报写豁免之前先确认判据本身没问反问题**——补丁要随它修的方案一起删。

## 覆盖率门禁守什么

基线在 `.coverage-baseline.json`，门禁是相对基线跌幅 ≤2pp，排除项在 `.c8rc.json`（`public/vendor/**` 是第三方压缩代码，不该计进我们的覆盖率）。

**这道门禁的价值不在数字，在于它真的会跑。** 它曾只挂在 `pull_request` 上，而矩阵默认的 fail-fast 又让另一条腿的抖动连坐取消它——**结构上从来没跑成过**，于是分支覆盖在 80 个提交里掉了 11 个百分点而没有任何东西变红。

**不要用碎测试去凑数字。** 缺口集中在 `server.js` 与 `src/agent/agent-appserver.js` 两个最大模块的错误路径上，补它是一项独立工作，不是清理。

**别提议加绝对覆盖率门槛。** 退化门禁已经包含绝对阈值，后者是它的真子集。覆盖率是一个容易被凑、且凑了不产生保护的指标——那 1807 行源码文本断言删掉后覆盖率只动了 0.03pp，**它连这个最宽松的指标都没骗到，只骗过了人**。

有一条读数字的教训值得单记：某次刷新基线时 functions 跌而 branches 涨了 5.84pp，**那是同一件事的两面**（新增的 CLI 宿主层进了分母，而它们的判定层被测得很厚），只看一个数字会得出相反的结论。
