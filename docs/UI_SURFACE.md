# 界面可见功能

手机屏幕上**真的能看到、能点**的东西，按屏幕区域拆到最小单位。

与 [FEATURES.md](FEATURES.md) 的分工：那份从代码出发，含大量用户看不见的后端机制（可靠投递、审计、协议桥接）；这份只收界面上存在的交互面。

**图怎么来的**：全部由 [`e2e/ui-shots.spec.js`](../e2e/ui-shots.spec.js) 对着 mock app-server 实跑产出，Pixel 5 视口（393×727，dpr 2）。图上的红框和编号是截图前注入页面的，**靠选择器定位**——选择器失效直接抛错，`npm run test:e2e` 变红。

改了 UI 之后重新生成：

```bash
npm run shots
```

`npm run test:e2e` 只验证不写盘。这样拆是因为 28 张里有 7 张每跑一次就变（项目名是随机临时目录、延迟毫秒数、thread id 时间戳、累积 token 数），每次 e2e 都吐 7 张图的 diff 只会让人养成无脑丢弃这个目录的习惯。**代价**：UI 只改了颜色或文案、选择器没动时，图会滞后到下次手动重跑——这种情况没有自动手段能发现。

**编号对应表格的 `#` 列**。自带文字标签的区域（工具面板、斜杠命令、设置选项）只圈红框不打编号——第一版给它们都编了号，结果气泡把按钮文字盖成了「Th①ds」。

`#` 列写 `—` 表示 mock 环境造不出这个状态，每节末尾写明原因。

![计划卡片 + 折叠起来的活动摘要 + 用时分隔](assets/ui/24-tool-cards.png)

![活动摘要展开后：MCP / 搜索 / Raw 各一行](assets/ui/24b-tool-cards-expanded.png)

![系统消息](assets/ui/12b-system-message.png)

**过程和结论分两种形态**（抄 ChatGPT 桌面端）：工具执行的过程收成**一行灰字**（活动行），可点开看详情；需要你处理的、或属于结论的，仍然是**卡片**。分界就在「用时 N 秒」那条分隔线上——它上面是过程，下面是最终回复。

| # | 元素 | 看到什么 |
|---|---|---|
| 1 | 用户气泡 | 右对齐 |
| 2 | 助手正文 | 全宽无气泡，Markdown 渲染：标题、表格、引用、列表、分隔线 |
| 3 | 代码块 | 语法高亮 + 复制按钮，暗底，超宽时自己横向滚动 |
| 4 | 宽表格 | 自己横向滚动，不撑破正文；溢出时边缘渐隐，提示还能往右滑 |
| 5 | thinking / reasoning | 可折叠，默认收起。三态：「正在思考」→「已思考 4秒」，量不到耗时时是「已完成思考」 |
| 6 | 命令活动行 | 收起时一行（跑挂了行首变红并缀「· 失败」），展开看命令、输出、退出码 |
| 7 | 文件变更活动行 | 一个文件显示路径，多个显示「编辑了 N 个文件」，展开看 diff |
| 8 | MCP 调用活动行 | `服务器名/工具名`，展开看参数与结果 |
| 9 | 搜索活动行 | 「已搜索网页：<query>」，展开看标题、URL、摘要 |
| 10 | 计划卡片 | 待办列表与状态（✓ 完成 / ⌛ 进行中 / □ 待办）。**仍是卡片**：它是当前状态，不是做过的事 |
| 11 | Raw 活动行 | 未识别的 item 降级显示，不静默丢弃。不进活动摘要 |
| 12 | 系统消息 | 灰色居中，错误为红色 |
| 13 | 活动摘要 | turn 结束后，相邻的活动行折成一句过去时（「已搜索网页、运行了命令」）。整组是同一个工具时改用计数（`read_file · 3 次调用`） |
| 14 | 「用时 N 秒」 | 活动区与最终回复之间的分隔线 |
| 15 | 复制按钮 | turn 末尾，复制本轮回复的 markdown 原文 |
| — | 等待态 | 发出消息到助手开口之间，显示「正在思考」四个字，一道微光从左扫到右（不是三个点）。**无图**：它只存在于 turn 开头的一瞬，截图脚本抓不稳 |
| — | turn 终态 | 完成 / 失败 / 中断的摘要 |

**只有一条活动时不折叠**：它本来就只占一行，再套一层「运行了命令 ▸」反而多一次点击才看得到内容。

**无图的原因**：turn 终态由 `summarizeTurnOutcome()` 从本轮聚合 diff 与命令退出码导出，mock 的回合不产生聚合 diff，卡片因此不渲染。

## 5. 会话设置面板

![会话设置：权限与模型](assets/ui/14-session-settings.png)

点设置胶囊打开。**权限**（4 项）：

| # | 选项 | 含义 |
|---|---|---|
| 1 | 请求批准 | 逐次审批（默认） |
| 1 | 帮我批准 | 自动审查 |
| 1 | 完全访问 | 免审批 + 完全沙箱（需二次确认） |
| 1 | 跟随主机配置 | 用宿主机 config.toml 的设置 |

图上 2 是下方那行状态说明：`所选设置将在下一轮生效` / `当前已生效` / `主机配置已应用`。主机策略禁止的模式显示为不可选并给出原因。

图上 3 是**模型**（来自 `model/list`，mock 下 4 个）。再往下还有**推理强度**（低/中/高/超高/最大）、**速度**（标准/快速）。

**会话模式**：对话模式（Chat）可选；计划模式（Plan）**固定禁用**，提示「当前稳定协议尚未提供已验证的模式切换能力」。

**高级设置**（默认折叠）：

![高级设置展开后](assets/ui/15-settings-advanced.png)

- 审批策略（图上 1）：仅信任命令 / 按请求批准 / 从不询问
- 审批人（图上 2）：由我审批 / 自动审查
- 细粒度审批：沙箱外操作、规则匹配、技能调用、权限申请、MCP 追问
- 沙箱：只读 / 工作区可写 / 完全访问
- 当前生效值：JSON 原文（未拿到时显示「等待当前会话返回配置」）

## ⚠ 界面上看不到的元素

实跑测量确认，以下在 HTML 里存在但用户看不到。列出来是为了避免误以为它们在工作：

| 元素 | 状态 | 说明 |
|---|---|---|
| `#thread-title` | 高 1px + overflow:hidden | 有内容（会话名）但视觉不可见 |
| `#state-label` | 高 1px + overflow:hidden | 有内容（idle/busy）但视觉不可见 |
| `#session-meta` | `display:none` | 全表无规则打开 |
| `#status-detail` | `display:none` | 全表无规则打开；上下文占用因此改放 composer |
| `#model-input` | `display:none` | HTML 注释标为 legacy 兼容字段 |
| `#perm-select` | `display:none` | 同上 |
| `#turn-announcer` | `.sr-only` | 有意的：只给屏幕阅读器 |

`#state-label` 虽然人眼看不见，但 `textContent` 仍在更新，所有 E2E（包括截图 spec）都靠读它来判断连接是否 idle。
